# CLAUDE.md

Automated Binance spot trading bot. Python 3.12, asyncio, SQLAlchemy + asyncpg, PostgreSQL, Alembic. Status: phase 5 of 6 (CSV export and Telegram alerts built; a test message verified on real Telegram 2026-10-19; trade alerts not yet seen); see [NEXT_STEPS.md](NEXT_STEPS.md) and [docs/README.md](docs/README.md).

## Git workflow

Full version in [docs/git-flow.md](docs/git-flow.md).

- Never push to `main` (GitHub refuses it). Work on a branch named `type/short-description` (kebab-case) and open a PR; merges are squash merges.
- Commit messages and PR titles: `type: short description`, max 72 chars, imperative, no period. Types: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`. The PR title becomes the commit on `main`.
- Before opening a PR run `.venv/bin/ruff check .` and `.venv/bin/pytest`; CI runs the same on a throwaway database.
- After a squash merge, local `main` must match `origin/main`: `git switch main && git pull --prune`.

## Commands

```bash
uv sync --python 3.12
.venv/bin/pytest
.venv/bin/ruff check .
.venv/bin/alembic upgrade head
.venv/bin/python -m bot.main               # startup checks, then the engine (Ctrl+C stops it)
.venv/bin/python -m bot.main --check-only   # startup checks only
.venv/bin/python -m bot.reports.tax_exporter --year 2026   # tax ledger to exports/tax_ledger_2026.csv
```

## Critical rules

- This code will trade real money. Money, prices, quantities and percentages are `Decimal`, never `float`.
- Every price and quantity goes through `bot/config/precision.py` (round, then `validate_order`) before it reaches Binance.
- Only `bot/services/binance_client.py` talks to Binance REST. It enforces filters and `DRY_RUN`; don't bypass it. Never use python-binance's `/sapi` helpers: they ignore `testnet=True` and hit the real exchange.
- The entry signal is a placeholder with no demonstrated edge (ADR-006): never describe it as profitable, and never switch to real money on it without the owner's explicit say-so.
- The bot never sells on its own except through the OCO it placed; unprotected positions are flagged, not liquidated.
- Engine state changes go through `TradingEngine._evaluate` under its lock; commit an order row *before* sending it (see ADR-005).
- Never send an order, or use real API keys, unless the user explicitly asks. Keep `DRY_RUN` and `BINANCE_TESTNET` defaulting to true.
- Never log or print secrets (`SecretStr`). The Telegram token is part of the request URL: never log a URL or an aiohttp error text from `notifications.py`.
- Observer hooks run under the engine's lock: they only enqueue (ADR-007).
- The app name (Tidewatch) lives only in `APP_NAME` (`bot/config/settings.py`), `pyproject.toml` and the compose project name.
- Verify Binance behaviour against the live API or current docs, and say what was checked vs assumed.
- Schema changes go through Alembic; read autogenerated migrations (see docs/guides/developer-guide.md for the enum-constraint quirk).
- `NEXT_STEPS.md` holds pending items only: delete entries when they are done. `SETUP_CHECKLIST.md` is the owner's list of external setup; keep it accurate when something becomes built, verified or changes how it is set up.
- PostgreSQL is always external: a connection string in `DATABASE_URL`, never a database service in compose. Locally it is the existing container on port 5432; in production a managed database or the Coolify `shared-postgres` (docs/coolify.md). Don't create another database container.

## Layout

`bot/config` (settings, precision), `bot/database` (connection, models), `bot/services` (binance_client, user_stream, reconciliation, risk_manager, scanner, indicators), `bot/engine` (state_machine, runner, ledger), `bot/engine`, `bot/reports`, `migrations/`, `scripts/` (local.sh, preflight.sh), `tests/`, `docs/`.
